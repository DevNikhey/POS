# Loesungshinweise - UE3_Rechner

Alle 5 Aufgaben vollstaendig implementiert; keine TODOs/NotImplementedException mehr. Geaendert wurden nur die 4 Schueler-Dateien: Token.cs, Programm.cs, Calc.cs, MainWindow.xaml.cs. Expression.cs, Grammatik.txt und MainWindow.xaml bleiben unveraendert (keine Aenderung noetig/erlaubt).\n\nWichtige Designentscheidungen / Fallstricke:\n- Aufgabe 1 (Token.Tokenize): EINE Regex, Keywords mit Wortgrenze \\b VOR dem Namens-Muster: \\b(?:LET|IF|THEN|ELSE)\\b|[a-zA-Z]\\w*|\\d+(?:\\.\\d+)?|[+\\-*/]|=|\\(|\\)|\\S+ . Das \\b verhindert, dass 'LETTER' als 'LET'+'TER' bzw. 'IFa' als 'IF'+'a' zerfaellt. Mehrstellige/Dezimalzahlen via \\d+(?:\\.\\d+)?. Typbestimmung pro Match ueber separate Keyword-Regex; alles Unbekannte (z.B. '@') -> ERROR. Per Python-Simulation der Regex/Parser-Semantik verifiziert.\n- Konsistente LET/IF-Konsumierung: Das fuehrende 'LET' wird im Programm-Dispatcher entfernt (LetStatement startet beim Namen); das fuehrende 'IF' wird im FactorExpression entfernt (IfExpression startet bei der Bedingung) - analog zum Robot-Referenzprojekt.\n- Recursive Descent: Add->Mul->Factor; Klammer entfernt '(' und ruft wieder AddExpression auf (Rekursion). Punkt-vor-Strich ergibt sich automatisch.\n- Aufgabe 4 Fallstrick: ELSE wird nur konsumiert, wenn tokens[0].Type==KEYWORD UND tokens[0].Value==\"ELSE\" (nicht nur Token-Typ). Verifiziert: 'IF 0 THEN 5' gefolgt von 'LET z = 9' liefert [0,9] ohne Fehler.\n- Vor jedem tokens[0]-Zugriff wird tokens.Count geprueft (kein IndexOutOfRange).\n- double.Parse mit CultureInfo.InvariantCulture (Dezimalpunkt), Ausgabe ebenfalls InvariantCulture.\n- GUI: Tokenize->ItemsSource; ERROR-Tokens -> MessageBox+return; Parse mit Liste OHNE ERROR-Tokens; Errors pruefen/Clear; vor Evaluate Variables.Clear(); Results zeilenweise in OutputTextBox.\n- Hinweis: FactorExpression nutzt 'Expression? inner' -> das Projekt muss <Nullable>enable</Nullable> haben (so vom Toolkit/--parser erzeugt); MainWindow.xaml.cs braucht keine nullable-Warnungen. Gebaut/getestet wird unter Windows (WPF); auf macOS war kein dotnet-SDK verfuegbar, daher Logik per Simulation verifiziert (Demo-Programm liefert korrekt 11, 5, 111).
